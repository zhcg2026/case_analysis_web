# 应用恢复备查资料

这是 2026-11-12 实际运行环境的脱敏参考，不是生产部署入口。日常继续使用现有容器；本目录归档不要求重建、重启或更改数据库。

## 内容与边界

| 文件 | 用途 |
|---|---|
| `compose.recovery.reference.yml` | 50 项实际挂载及当前命令、网络、端口、健康检查和非敏感环境参数 |
| `runtime-baseline.json` | 同日运行配置的精简脱敏基线，用于离线比较 |
| `observed-python-packages.txt` | 110 个已安装 Python 发行包的观测版本，不是已验证的全新安装锁文件 |
| `observed-debian-packages.json` | 观测的系统包版本，不包含软件仓库凭据或机器环境文件 |
| `schema-verification.json` | Compose 1.29.2 只读解析及参数比对记录，不是恢复演练证明 |
| `preflight.py` | 仅在本地读取、比较并输出 JSON；无 SSH、Docker、数据库或文件写入调用 |
| `tests/test_preflight.py` | 纯内存配置测试，不使用生产数据或服务 |

密码、令牌和私钥不写在这里，配置只引用部署主机受控的 `.env.production` 路径。镜像、运行文件系统、数据库备份、密钥包、完整原始 inspect 和私人备份目录资料均不入仓库。加密恢复资产已另行保全，其位置和解密要求以本地知识库记录为准。

## 本地静态检查

在项目根目录、已有 Python 和 PyYAML 的环境中运行：

```powershell
.venv/Scripts/python.exe ops/recovery/preflight.py
.venv/Scripts/python.exe -m unittest discover -s ops/recovery/tests -v
```

检查旧配置的差异可使用：

```powershell
.venv/Scripts/python.exe ops/recovery/preflight.py --compose docker-compose.internal.yml
```

退出码 0 仅表示静态配置匹配该时点基线；2 表示不匹配或输入不可解析。输出始终保留 `ready_to_rebuild: false`，不会因检查通过而执行任何操作。检查不读取环境文件内容，也不验证部署主机路径当前是否存在。环境比较只检查显式值，单列“缺少显式键”和“值不同”；缺少显式键不代表实际运行环境一定缺失该值，环境文件和镜像继承仍需另行核对。

## 防止误用

- 备查 Compose 没有 `build` 或在线安装步骤，必须明确提供已经验证的恢复镜像；不设置 `CASE_ANALYSIS_RECOVERY_IMAGE` 时，Compose 解析会被阻止。不要随意设置该变量然后接管健康容器。
- 原镜像与运行容器存在后装依赖差异。保全原镜像不等于完整保全当前运行层，恢复时需要结合独立保全的运行文件系统和版本清单验证。
- 现有容器没有 Compose 管理标签。不能假设这份文件能无缝接管当前容器，也不能将解析通过视为升级、删除或重建许可。
- `models.py` 和 `models_init.py` 目前是历史空目录挂载，本参考保留它们，不自动清理；其余旧配置中不属于当前容器的 17 项挂载未加入本参考。
- 挂载的上传照片、模板、报告和数据库持久化数据，不在 Docker 镜像/运行层导出里。应用容器恢复与整机数据灾备是两项工作，不能互相替代。
- 版本清单记录当时环境，未验证所有包可以从头精确重装。原 Dockerfile/requirements 的构建重现问题仍须单独评审。

## 正式恢复前必须另行核验

1. 确认故障/恢复范围及授权，保留原容器和回退资产，不能为了测试预案而删除正常容器。
2. 核对 50 个宿主机挂载源、路径类型、环境文件及依赖服务的网络和持久化目录。
3. 验证恢复镜像、运行层依赖、备份认证和解密条件；跨机器恢复还需独立的受控密钥托管。
4. 在隔离条件下验证恢复后的版本、记录数量及功能，再设计正式操作和回退步骤。

自动备份并发缺陷的修复候选属于另一批工作，本目录不包含补丁或部署动作。后续运行配置变化时，应重新核对、脱敏并更新基线；不要把本快照长期当作自动生效配置。
