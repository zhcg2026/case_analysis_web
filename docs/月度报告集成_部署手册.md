## 一、部署前服务器检查（只读，不改任何东西）

```bash
ssh ubuntu@192.168.101.3

# 1. 确认 case_data 表有 is_overtime 列且已填真值
docker exec mysql-case-analysis mysql -u root -pf1dd8623fcfee83e658817da case_analysis \
  -e "SHOW COLUMNS FROM case_data LIKE 'is_overtime';"

# 2. 确认 202608 批次存在，is_overtime 有非全零值
docker exec mysql-case-analysis mysql -u root -pf1dd8623fcfee83e658817da case_analysis \
  -e "SELECT is_overtime, COUNT(*) FROM case_data WHERE upload_batch='202608' GROUP BY is_overtime;"

# 预期：应有 is_overtime=1 且 COUNT=216（与本地验证一致）
# 如果 is_overtime 全为 0，说明该批次导入时未携带真值，需从产线重新导入带 is_overtime 的数据后再继续
```

## 六、回滚（如出问题）

回滚目标：恢复到本次部署前的状态，月报功能不可用但不影响任何现有功能。

```bash
ssh ubuntu@192.168.101.3

# 1. 恢复备份的 app.py 和 analysis_routes.py
BACKUP=/home/ubuntu/backup_月度报告_$(date +%Y%m%d)
cp $BACKUP/app.py /home/ubuntu/case_analysis_web/backend/
cp $BACKUP/analysis_routes.py /home/ubuntu/case_analysis_web/backend/

# 2. 恢复旧前端 dist
cp -r $BACKUP/dist/* /home/ubuntu/case_analysis_web/frontend/dist/

# 3. 用备份的原始 docker run 命令重建容器（去掉两行新 -v）
docker stop case-analysis-web && docker rm case-analysis-web
# 从 $BACKUP/docker_cmd.txt 中复制原始命令执行，或手动去掉以下两行后执行：
#   -v ./backend/monthly_report:/app/backend/monthly_report \
#   -v ./backend/reports:/app/backend/reports \

# 4. 确认系统恢复正常
docker logs case-analysis-web --tail 10
curl http://localhost:5001/health
```

新模块目录 `monthly_report/` 和 `reports/` 留在磁盘上无害，可随时删除：
```bash
rm -rf /home/ubuntu/case_analysis_web/backend/monthly_report
rm -rf /home/ubuntu/case_analysis_web/backend/reports
```
